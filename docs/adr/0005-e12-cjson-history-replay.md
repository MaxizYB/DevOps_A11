# ADR 0005：整合 B11 cJSON 适配与历史缓存/部署追溯

- 日期：2026-11-15
- 整理/实现：A11 组长 241880439，AI 辅助；不是 B11 成员的个人 ADR。
- B11 来源：7b45b9c04686f3aefe861bb1d8a17aa63c969f23，交接 ZIP d658d63ab2f651f5368f04dcc9a6de844b407aa8513c1b8eec36be81b87e4e02。

## 背景

B11 回传课程样例客户端记录、E11-B 原始结果、cJSON 专用适配和本地五阶段证据。A11 已有更严格的路径/产物/元数据校验，不能用 B11 的早期 pipeline/server 直接覆盖。原 cJSON scan 每次执行 GCC，旧报告只用于 finding 差异，不能证明图缓存复用。

## 决策

1. 以 A11 编排/API 为主，只迁入有明确来源的 cJSON 适配、Dockerfile 和 B11 扩展测试。分析目标明确限定 cJSON_Utils.o，不声称通用支持或整个 cJSON 构建图。
2. 以 Make 实际展开的编译命令为 GCC oracle 参数。缓存键包含编译命令、编译器版本、相关环境、所有本地头文件内容、源码集合和预处理行（含续行）；函数体变化可复用，头文件/参数变化保守刷新。基线 actual 来自 BuildChecker 并经 GCC 交叉验证。
3. 增量报告记录 base commit 和 cache SHA；修复输入必须是同轮 target 的报告，不能用固定 MD 替代 E12。保留 patch 验证、回滚、最终全量重检和所有原始哈希。
4. 保留 configuration_id，并另记录实际实现文件内容指纹/source SHA/B11 来源 SHA。客户端实际比对部署指纹，不把手填 B11 版本当部署证明。
5. 上游 base/target 保持原样，Dockerfile 由实验 harness 注入隔离副本。Docker Hub/包源不可用时另建具名数据集并记录镜像摘要、包源和候选哈希，不删除或改写失败证据。
6. 组长选择现有开源历史缺陷复现；这不证明本组实际维护 cJSON，也不声称教师已认可选题例外。技术成功和选题要求分别说明。

## 后果

客户端与共享 API 跨机调用，内部四组件使用函数及带哈希产物自动衔接。B11 必须对最终部署再跑一次独立客户端并回传；A11 云端自验不作为其确认。B11 报告/ADR/个人协作记录仍由 B11 提供。
