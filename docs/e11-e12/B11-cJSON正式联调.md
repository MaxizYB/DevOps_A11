## 你们现在需要做什么

1. 收到我们新版的 A11-给B11-cJSON正式联调-20261115.zip 并解压。此包没有密码；继续使用之前私下提供的 b11-e12 转发账号，不使用 root，也不需要 Docker。
2. 建立原来的 SSH 隧道。保留这个终端，成功时不显示输出是正常的：

    ssh -N -T -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 127.0.0.1:18080:127.0.0.1:8080 b11-e12@47.110.157.207

3. 在另一个终端进入解压目录，执行（把学号换成实际操作者）：

    python3 run_peer_client.py --operator 241880100

Windows 可将 python3 换成 python 或 py -3。不要改请求中的提交或项目路径。程序会先核对已部署代码的内容指纹，防止请求跑在旧服务上；随后自动提交、查状态、检查相同键重用及 409、下载并核对全部产物、检查五阶段与本轮报告衔接。

4. 将自动生成的 B11-E12-cJSON-联调记录-*.zip 回给我们，同时填写包内 B11回执模板.md。失败也原样回传，不要修改结果或只发截图。顺便确认个人报告/ADR/AI 记录是否已齐全，未包含在第一次交接包的材料请补发路径或文件。

这是一轮功能/接口完整联调，不是并发压力测试，不要启动多个客户端同时压测。每轮唯一键会创建独立任务，遇到问题保留失败记录，修复后再开新一轮。
